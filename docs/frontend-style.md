# 前端风格指南

> 2026-10-28 按新整理路线修订；与 [design.md](design.md) v0.10、[ADR 0010](decisions/0010-图片直接属性与原名增量导入.md) 配套；旧库处理按 ADR 0009，不另建旧图库兼容界面。本文是**交互约定，不是全部已实现功能清单**；T1 已实现范围、暂停 PR 及待评审项见 [transition.md](transition.md)。
> T2 独立检查已接入：电脑左图右资料、手机上下排列；草稿独立持久化、保存与归档分开。既有主题、网格、预览与移动端交互保留；业务导航从平台目录转为收件箱／已归档，检查以图片为单位。

## 1. 总原则

首要目标是减少用户无用或繁琐的操作，即使代码多做工作。图片直接有 tag／画师／来源，不先建组。

这是图片优先的本地工具：界面退到背景，作品当主角。不是官网，不要营销页式的大图、大留白、渐变横幅。

## 2. 视觉

- **两套主题，默认跟随系统**（`prefers-color-scheme`），设置里可手动切换为"深色 / 浅色 / 跟随系统"，选择存在浏览器本地。
- 深色底用中性深灰（约 `#14151a`），不用纯黑；浅色底用近白，不用纯白。
- 全局只有一个强调色，用于选中态、主按钮、tag 高亮。低饱和、克制。
- 扁平、小圆角（4–8px）、少阴影；分层靠 1px 细边框和明度差。
- 字体用系统字体栈（`system-ui, "PingFang SC", "Microsoft YaHei", sans-serif`），**不引入网络字体**。
- 所有颜色、间距、圆角写成 CSS 变量（`--bg`、`--fg`、`--accent`、`--radius`、`--gap` 等）。换肤和手机适配只改变量。

## 3. 缩略图网格

- 默认**原比例**显示（画作比例差异大，方形裁切会毁构图），可切换为方形。M1 用 CSS grid 实现；等高行（justified）布局留到 M2 浏览页。
- 网格密度可调（滑块或 `Ctrl+滚轮`），设置记在浏览器本地。
- **预留空间防跳动**：用数据库里的 `width` / `height` 先撑出占位，未加载时填中性灰；视频没有宽高，用固定比例占位。
- **来源建议标志**：缩略图左下角保留品牌色方块＋首字母，白描边与阴影保证对比；不使用横跨画面的文字条，也不内嵌各站点官方 Logo。只知站点、缺作品 ID 时可继续用待补充小点，但它不表示已核查。自定义平台显示名首字母与稳定颜色仍集中在 `lib/platforms.js`；多来源标志如何同时展示，待检查页草图评审，不能再默认一图只有一个平台。
- **收件箱筛选条**：顶部"全部 / 有来源建议 / 没有建议"，各带张数（始终是收件箱整体统计，不随筛选变化）。只在收件箱视图出现。筛选在服务端做（分页下前端过滤会漏图），写进地址栏。
- 视频和 GIF 没有缩略图（API 返回 `thumb_url: null`），显示格式图标占位。图片未设置展示版本时也保留卡片，明确显示“展示文件待设置”，不猜选其他版本；详情／预览展示同样说明且不加载空媒体地址，仍允许选择、关闭或切到下一张。
- **一图一卡，标题固定一行常驻**：悬停、选中、取消选择和长文本都不能撑高卡片。收件箱有疑似 ID 时优先显示并明确标为“疑似”，无 ID 显示原文件名；完整原名可在提示与详情查看。来源标签可以展示 ID，但不能把未核查信息画成已确认。T1 已适配固定标题，详情展示全部来源建议，紧凑标题不代表指定主来源。
- **页码是来源附属属性**：对应 Pixiv／X 等来源旁可显示 pn，未知不填 p0，不是总页数或独立 tag；不做组页码。按发布 ID 找图不要求 pn，正常归档也不强制填写。
- 不做虚拟滚动、blurhash 占位（见第 9 节）。
- 手机（窄屏）上缩略图列宽上限为屏幕宽度的 44%，保证至少两列；右侧面板在首次打开时默认收起，把空间让给图片。

## 4. 收件箱与批量整理（M1 重点）

- **选中态**：强调色描边 + 左上角对勾，一眼可辨。
- **布局**：左边网格，右边可收起的操作面板；选中项变多时，面板顶部显示"已选 N 张"。窄屏（手机）改为底部抽屉。
- **单选详情**：在尺寸之外显示当前展示文件版本的大小（KiB／MiB 等二进制单位与精确字节数），只按需读取，换图立即清掉旧值并使旧请求失效；缺失／权限／网络失败可解释，不误报为零。文件大小不是原图证明；T2 已按版本关系适配，不整批合并暂停分支。
- **键盘优先**：检查默认按单张前进，多选批量操作不暗中改变作用范围。来源、tag 输入快捷键随检查页评审，不照搬旧“Enter 确认下一组”。
  - 多行链接框的普通 `Enter` 必须是换行，`Ctrl+V` 必须正常粘贴文本，不能被全局“确认／归档”抢走。保存并下一张的快捷键待定，保存不隐式归档；`Esc` 在非编辑场景继续取消选择；
  - `Ctrl+A` 全选；`Shift+点击` 范围选；`Ctrl+点击` 增减；方向键移动焦点；`空格` 预览当前图。
  - `/` 单键或 `Shift+/` 打开快捷键帮助，再按任意一种操作关闭；`Esc`、关闭按钮、点击遮罩也可关闭。长按不反复开关。焦点在文本框里时斜杠和问号仍正常输入，不抢按键；滑块有焦点时帮助开关键仍有效。帮助盖在大图预览上时，按键只作用于帮助，不切图、不缩放，关闭帮助后继续原来的预览。
- **操作结果就地预览**：面板展示将追加的来源、核查缺项与所选图片影响范围，不再预览按平台命名的归档路径。正常归档和强制归档是明确区分的动作，不因核查保存而自动执行。
- **检查页的多行链接框**：一行一个链接，逐行显示解析／错误；新框只追加，已有来源独立列出并明确解除。缺平台页码保留未知，不自动 p0。多选提交前必须说明“全部链接添加给每张所选图片”，明确确认后执行，不按行分配。
- **批量缺项不自动分流**：显示各图片缺项，保留选择，让用户另选正常或强制归档范围。至少一条已人工确认的具体发布允许正常归档，页码和时间可空，额外待核查来源继续显示，不被一并确认。
- **直接属性的批量范围**：给所选图片分别加／删角色 tag、绑定画师，不建组、不继承、不修改未选图。
- **手机**：长按进入多选。触控目标不小于 44px。

### 大图预览（缩放与平移）
- 打开方式：空格或双击。默认"适应窗口"（只缩小，不放大小图）。
- **缩放**：滚轮以光标位置为中心；`+` `-` 按档（1.25 倍）；顶栏有缩小 / 百分比 / 放大 / 适应窗口按钮。上限为适应窗口的 16 倍。
- **100% 的含义**：图片 1 像素 = 屏幕 1 像素。双击在"适应窗口"和 100% 之间切换；图本来就比窗口小（适应窗口已是 100%）时，双击放大到 200%。
- **平移**：放大后按住拖动，或方向键。拖动范围受限：图比窗口大的方向不能拖出空白，更小的方向固定居中，不会把图拖丢。
- **手机**：双指捏合缩放（以两指中点为中心）、单指拖动、双击切换。预览区接管触摸手势，页面本身不会被缩放。
- **Esc 分两步**：放大状态下先回到适应窗口，再按一次才关闭预览。放大后方向键用于平移而不是切图；切回适应窗口后方向键才切图。放大时左右切图按钮隐藏，避免拖动时误点。
- 切到另一张图时自动回到适应窗口。视频不支持缩放（用浏览器自带的播放控件）。
- 计算逻辑集中在 `frontend/src/lib/zoom.js`（纯函数，有单元测试），组件只负责接事件。

## 5. 确认与撤销（分三档）

**不是"一律用撤销代替确认"**：不可逆的操作必须由用户确认（ADR 0005），大范围操作保留清单确认。完整规则以 [ADR 0007](decisions/0007-按可撤销性决定是否确认.md) 为准，这里只写界面上怎么表现：

| 类别 | 例子 | 做法 |
|---|---|---|
| **小范围、可撤销**（图库内改动，记入 op_log，且**对应撤销已实现**） | 归档、来源编辑、打 tag、改画师（各自撤销交付之后） | 默认无需额外弹框，显式范围确认另计。完成后提示“已归档 3 张　[撤销]”；提示消失后仍可倒序连续撤销 |
| **大范围、可撤销** | 改模板后重排全库、批量移动整个文件夹 | 先显示完整"A → B"清单，确认后执行 |
| **不可撤销**（碰到图库之外或永久删除） | 删除源文件、清空回收站、永久删除记录 | **必须显式确认**，说明会发生什么，默认不选中"删除" |

要点：
- **撤销没交付的操作不得免确认。** 归档与其撤销在 T2 同时交付，其他关系操作按各阶段交付对应撤销；之前按“大范围”处理，清单确认后执行。多选追加来源的范围确认是独立要求，即便已有撤销也不能省去；强制归档只放宽资料门槛，不放宽安全规则。
- **撤销失败不强行还原**：文件不在预期位置、内容变了或目标被占用时，保持现状并明确告诉用户原因，不覆盖、不删除任何文件。
- **不可逆记录（如 `delete_source`）不进撤销栈**，撤销到它为止；界面上要明确告知"更早的操作已无法撤销"。

## 6. 页面与导航

- 主导航目标为**收件箱／已归档**，显示按逻辑图片去重后的张数；收件箱始终在最上面，保留有无来源建议筛选。不按平台文件夹分互斥归属。
  - T1 已删除旧文件夹树／面包屑与文件夹 API；旧 `?folder=` 书签明确提示旧视图移除并回收件箱，不偷换成平台来源筛选。
  - 来源上下文在详情可见，pn 在对应平台来源旁，不另建组导航；标题只显示稳定首条可用来源作摘要，多条建议显示数量，完整内容在详情列出。
  - 手机导航继续以抽屉盖在图上，点入口展开、选择后收起，遮罩和 Esc 可关闭。
  - 已归档可继续补资料；强制归档不清除待核查状态，不增加第三个“强制归档图库”。没有图时给说明而非空白。
- “画师／Tag／搜索”随对应功能交付添加，不放灰掉的空入口；同图在任意平台查询里都引用同一身份。手机端届时再评估是否底部 Tab。
- 画师页像"主页"：名字、各平台账号链接、作品数，下接作品网格（M2）。
- Tag 用胶囊（chip）组件，按命名空间区分颜色，低饱和；输入时自动补全，支持别名。
- 搜索栏全局固定，已解析的条件显示为 chip（M2）。

## 7. 响应式与无障碍

- 移动优先的 CSS：`grid` + `clamp()`，不写死像素宽度。
- 过渡动画 ≤150ms，并尊重 `prefers-reduced-motion`。
- 不使用会遮挡图片的常驻浮层。
- 所有资源本地打包，**不依赖 CDN**（要支持离线和局域网）。

## 8. 技术选型

| 用途 | 选择 | 说明 |
|---|---|---|
| 框架 | Vue 3（`<script setup>`）+ Vite | ADR 0001 |
| 路由 | 当前手写 `lib/location.js`＋`lib/history.js` | 未引入 vue-router；检查页与关系视图增加时先评估，不把依赖预留当成交付 |
| 状态 | Pinia | 选中集合、缩略图大小、主题等 UI 状态 |
| 样式 | 原生 CSS 变量 + scoped style | 不引入组件库或 Tailwind / UnoCSS |
| 图标 | `@lucide/vue`，按需导入 | 与现有依赖一致，资源本地打包 |
| 组件 | 手写 | 网格、浮动栏、输入框、tag 胶囊、提示条，数量少 |

**为什么不用 Naive UI / Element Plus**：前端构建产物要提交进仓库（让手机 Termux 无需 Node 即可使用）。大型组件库会让产物体积大幅增加，每次改界面仓库都跟着膨胀；而本项目的界面组件很少，手写更可控。

## 9. 明确推迟的内容

| 内容 | 推迟原因 | 何时做 |

| blurhash / 主色占位 | 需导入时额外计算并存库（要加迁移）；宽高占位已能防跳动 | 有明确需求时 |
| ~~lightbox 的缩放、拖拽~~ | ~~M1 只需判断"这是哪张图"~~ | **已在 M1b 后提前完成**（2026-10-27）：实际使用中发现看不清细节不够用，见第 4 节"大图预览" |
| 等高行（justified）布局 | 实现成本高 | M2 浏览页 |
