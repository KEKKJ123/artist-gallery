# 前端可视化设计：操作完成提示（Toast）

> **状态：设计提案，尚未实现，待红豆确认。** 按 [AGENTS.md](../AGENTS.md)，界面风格与交互约定的变更需先确认；本文不改变 [frontend-style.md](frontend-style.md) 已有条款，只补充其第 5 节“完成后提示”的具体落地方式。
> 配套文档：状态转移见 [frontend-state-transitions.md](frontend-state-transitions.md)，调试方法见 [frontend-debugging.md](frontend-debugging.md)。

## 1. 目标与现状

**目标**：归档成功后，在页面右上角显示一个小提示，不遮挡、不阻断页面其他交互，约 3 秒后自动消失。

**现状**（对应 `frontend/src/stores/review.js`、`App.vue`、`OperationDialogs.vue`）：

| 场景 | 现在的表现 | 问题 |
|---|---|---|
| 单张正常归档 | 清单弹窗短暂出现，随后自动执行并关闭；成功信息只是工具栏里的一行小字 | 弹窗闪现，成功信息不显眼，也不会自动消失 |
| 多张／强制归档 | 清单弹窗，确认后执行 | 行为正确，成功后同样只有工具栏小字 |
| 撤销、保存、恢复 | 同样写入工具栏小字 `review.notice` | 提示不统一 |

闪现的原因：`prepareArchive` 先把计划赋给 `archivePlan`（弹窗以 `v-if="review.archivePlan"` 显示），再自动调用 `archive()`，成功后清空 `archivePlan`。详见状态文档第 3 节。

## 2. 视觉与位置

```text
┌──────────────────────────────────────────────┐
│ 收件箱  共 30 张        …  ◐ ⟳ ? ▥          │ ← TopBar（不能被盖住）
├──────────────────────────────────────────────┤
│ [开始逐图检查] … [撤销最近一次]   ┌──────────────────┐
│                                   │ ✓ 已归档 1 张 [撤销]│ ← Toast
│                                   └──────────────────┘
│            缩略图网格（可正常点击、滚动）            │
```

- **位置**：右上角、**位于顶栏下方**，不是紧贴窗口顶边。TopBar 右侧有缩略图大小滑块以及方形裁切、主题、刷新、快捷键、侧栏按钮，提示框如果贴着顶边会盖住它们，与“不遮挡交互”相矛盾。
  - 建议 `position: fixed; right: 12px; top: 56px`。56px 只是估计值，实现时必须在桌面、窄屏、检查页（顶栏隐藏、改用 `review-header`）三种布局里实际量过再定，可考虑用 CSS 变量统一。
- **尺寸**：`max-width: min(360px, calc(100vw - 24px))`，文字不超过两行，长文案换行而不是撑宽。
- **配色**：只用 `theme.css` 里已有变量（`--bg-elev`、`--fg`、`--border`、`--radius`），深浅色主题自动适配；不新增颜色。
- **层级**：现有 z-index 为导航抽屉 30/31、预览 50、操作弹窗 55、快捷键帮助 60。提示框取 **58**：高于预览和操作弹窗（可见），低于快捷键帮助。
- **动画**：淡入加 6px 位移，≤150ms；`prefers-reduced-motion` 下取消（`theme.css` 已全局压低过渡时长，仍应在组件里显式处理）。

## 3. 交互规则

| 项目 | 规则 |
|---|---|
| 不遮挡交互 | 外层容器 `pointer-events: none`，仅提示框本身 `pointer-events: auto`；**没有遮罩层**，不抢焦点，不拦截键盘快捷键 |
| 显示时长 | 默认 3000ms 后消失；新提示出现时**重新计时**，相同文字也重新计时（用递增序号 `seq` 触发，不靠文字比较） |
| 悬停／聚焦暂停 | 可选。带“撤销”按钮时 3 秒偏短，建议鼠标悬停或按钮获得焦点时暂停计时，离开后重新计满。**待确认是否采用** |
| 撤销入口 | 按 frontend-style 第 5 节写成“已归档 N 张 [撤销]”。提示消失后，工具栏的“撤销最近一次”仍可用，并支持倒序连续撤销 |
| 多条提示 | 只保留最新一条，不堆叠、不排队 |
| 无障碍 | 外层常驻 `role="status"` + `aria-live="polite"`（节点要先存在，读屏器才会播报）；撤销按钮可键盘到达 |
| 手机 | 宽度跟随屏幕；触屏下按钮保持 44px 触控尺寸（`theme.css` 已有规则），顶部偏移要避开顶栏换行 |

### 哪些信息用 Toast，哪些不用

| 类别 | 展示方式 | 理由 |
|---|---|---|
| 归档、撤销、保存、恢复成功 | **Toast**，3 秒消失 | 结果已落库，用户只需知晓 |
| 失败、版本冲突、图库切换 | 保持现有红色／琥珀提示条（`review.error`），**不自动消失** | 用户必须看到并处理，3 秒会漏看 |
| 草稿同步状态 | 保持检查页内的 `draft-status` | 持续状态，不是一次性事件 |
| 强制／多图归档的清单、多选追加来源范围确认、文件恢复 | 保持模态弹窗 | 属 ADR 0007 要求的确认，不能改成提示 |

## 4. 组件方案（手写，不新增依赖）

遵循 frontend-style 第 8 节“组件手写、运行依赖尽量少”：

```text
components/ToastNotice.vue      新增：只负责显示、计时、触发 undo 事件
stores/review.js                新增 announce(text, { undoable })，统一替换各处 notice 赋值
App.vue                         挂载 ToastNotice，删除工具栏里的 notice 小字
```

组件接口：

| props／事件 | 含义 |
|---|---|
| `message: string` | 提示文字 |
| `seq: number` | 每次提示递增，驱动重新显示与计时 |
| `canUndo: boolean` | 是否显示“撤销”按钮（需同时满足 `operations.can_undo`） |
| `disabled: boolean` | 传入 `review.busy`，操作进行中禁用撤销 |
| `duration: number` | 默认 3000 |
| `@undo` | 调用现有 `undo()` 流程，不新增接口 |

要点：
- 计时器放在组件内，并在卸载时清理，不留全局监听（与 modules.md 对 composable 的约定一致）。
- store 只保存“最近一条提示及序号”，不关心如何显示；组件不 import store，由 App 传 props，避免组件反向依赖状态。

## 5. 同时要修正的行为

提示框只解决“成功反馈”。要消除弹窗闪现，必须一并改变归档流程：单张正常归档且预检无缺项时，**不再把计划写入 `archivePlan`**，直接执行；需要用户确认的情况才写入并显示清单。这属于状态逻辑调整，设计见 [frontend-state-transitions.md](frontend-state-transitions.md)。

## 6. 测试要点（实现时）

- store：单张正常归档的全过程中 `archivePlan` 始终为空；强制、多图、有缺项仍会产生清单。
- store：成功后 `announce` 被调用，序号递增；失败走 `error`，不走 Toast。
- 组件（vitest 假计时器）：出现后 3000ms 消失；新提示重置计时；相同文字也重新计时；卸载后无遗留计时器。
- 组件：外层容器 `pointer-events: none`，提示框可点击撤销；`aria-live` 容器始终存在。
- 手动：顶栏所有按钮在提示显示期间仍可点击；检查页、窄屏、深浅色主题各看一遍。

## 7. 明确不做

- 不引入第三方 Toast／组件库（见 frontend-style 第 8 节）。
- 不为提示增加持久化、历史列表或通知中心。
- 不改变归档的确认规则：多图和强制归档的清单确认不能因为有撤销或有 Toast 而取消（ADR 0007、AGENTS 规则 10）。
- 改动 `frontend/` 后须 `npm test`、`npm run build` 并提交 `src/artist_gallery/server/static/`，否则 CI 的 `frontend` 任务会失败。
