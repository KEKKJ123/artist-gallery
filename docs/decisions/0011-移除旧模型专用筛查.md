# 0011 移除改路线前旧模型的专用筛查

- 日期：2026-10-28
- 状态：采纳；补充取代 ADR 0009、0010 中专门识别旧 v1～v4 库及保留对应测试的要求。

## 背景与决定

红豆确认已手动删除改路线前的旧开发库，不再存在旧库转换、恢复或使用需求。因此删除旧模型专门识别分支、旧 schema fixture 和相应测试，不再为已弃用格式维护一套兼容／筛查系统。

当前格式的 application_id、版本号基线 5 保持不变；未知格式统一报错，不清空重建。当前格式今后从 v5 演进到新版本时，仍需版本校验与迁移，不把“旧开发库已删除”解释成以后可以丢弃数据。

版本检查分两步：先按数据库自身版本检查输入结构，逐条迁移，再在提交前检查目标版本结构；目标检查失败时该条迁移与版本号一同回滚。每个新版本的结构要求单独追加，不能把未来字段反填到基线要求中，拦住负责新增该字段的迁移。

本次不改变 schema、application_id、user_version 或现有 v5 数据；历史 ADR 原文保持不动，旧实现可在 Git 历史查阅。

## 提交约定澄清

复杂改动在同一个 PR 内拆成职责清晰、带对应测试的多个 commit；main 仍可 Squash 合并。用户关心的是 PR 内有可审查、可追溯的拆分行为，不要求 main 永久保留每个 commit。
