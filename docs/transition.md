# 新模型实施与验收（2026-10-28）

需求以 [design.md](design.md) v0.10 为准，简化决定见 [ADR 0010](decisions/0010-图片直接属性与原名增量导入.md)。旧库不迁移，且按 [ADR 0011](decisions/0011-移除旧模型专用筛查.md) 移除旧模型专门筛查与 fixture；T0 的多组共享 tag 与页码必填安排已被取代，不再当作实现依据。

## T1 已交付基线（历史范围，T2 在下方追加）

- 新格式 application_id=`0x41475259`、user_version=5；只读预检当前格式、版本及该版本结构，init 不覆盖非空目录；不转换旧记录或保留改路线前旧模型的专门识别／fixture。
- 图片与文件版本分离；直接图片 tag、画师与账号、平台发布／可空页码／时间、核查状态、证据和导入记录。无作品组／隐式组／标签继承。
- 新文件保留可用原名和扩展名大小写，所有识别结果进入收件箱；重名必要后缀、跨平台安全字符与长度限制。
- 外部目录再次选择：hash＋实际副本校验；复用已存在身份，保留画师、内容 tag、人工来源与归档状态，新增名称／证据不丢，同输入／规则去重。外部减少不删图库，不是镜像或后台监控。
- 副本损坏／缺失报错、不自动覆盖，不将重复源文件列为可删除。独占目标复制、校验落盘和确认后重新校验删源；预演只读不写库。
- 列表先按图片分页，再批量读多来源／tag／画师，不因关系数量重复卡片；来源建议是数组，不隐藏为旧单条字段。
- 导航与只读浏览为收件箱／已归档；保留有无建议筛选。新 `/api/navigation`、`/api/archived`；删除旧文件夹入口，旧书签明确提示失效。
- 固定一行来源 ID／疑似 ID／原名标题；现有选择、预览、触摸缩放、帮助与竞态守护继续保留。

**T1 当时不包含**：检查页、多行链接提交、人工确认、归档／强制归档／撤销，现由 T2 交付。画师／角色编辑、相似判定或版本合并仍未交付。结构中有关系不等于编辑入口已实现，不用 SQL 手改图库代替产品功能。

## T2 核查与归档（已实现，本地验收）

- 独立检查：桌面左图右资料、手机上下排列；入口有选择时只检查所选，无选择时检查当前已加载列表，冻结队列，不偷偷扩选未加载图片。
- 当前图库版本 6：保留基线 5，通过事务追加图库标识、独立图片草稿和线索撤回标志；不搬文件、不丢既有整理结果。未知／损坏／过新库不写入，图库标识损坏不重生成。
- 草稿每次输入本地兜底，服务端串行按版本保存；刷新／关页后恢复，其他页面冲突不覆盖；放弃草稿不删除正式资料，也不能清掉其他页面的新草稿。
- 正式保存检查资料修订指纹；共享发布时间按帖子列明图片编号范围并确认。已解除链接重加重连原依据，不重复证据。

- 默认逐图检查，来源预填，一行一个链接追加；坏行独立报错，已有来源单独解除。
- 多选是有效链接 × 每张所选图，明确确认范围；pn 可空，不猜 p0。用户核对具体帖子即可确认，时间与页码不额外制造门槛。
- 至少一条已确认具体发布可正常归档，无来源允许显式强制；批量混合缺项先列清单，用户另选，不自动部分执行。
- 两区文件移动与日志／撤销成套：复制校验、目标占用、失败与中断恢复；不误以为 SQLite 事务能撤回磁盘操作。
- 保存／下一张不隐式归档；补来源不自动退回收件箱；文件大小在单选详情和检查页按当前展示版本读取，切图清旧值、旧响应无效，缺失不误报零。暂停分支未合并、未改写。
- 单图正常归档不增加额外弹窗，配套倒序撤销；多图／强制保留完整清单确认，混合缺项不自动分流。文件中断留下 pending，先核对清单后选择继续或恢复操作前；所有权未登记、被占用或内容变化时保留现状，不自动强删或修复。
- 当前本地验证：pytest 298 项、vitest 237 项；真实 Edge 浏览器 29 项完整流程检查通过，含刷新／关页草稿、核查、正常／强制归档、撤销、混合批次和恢复，桌面／360、390 宽度深浅主题及清单截图实际查看。重复构建与提交产物逐文件 hash 一致，BOM／LF 检查通过；从临时源码副本打 wheel、全新 venv 安装声明依赖后独立验证新建库→导入→页面→核查→归档→撤销通过（首次验收环境漏装 Pillow，补齐后复验通过）。无 Android 真机运行或跨系统 CI 验收，不以手机视口模拟替代真机。

## T1 一致性修复（同一 PR 内分四个 commit）

1. 源文件删除先持久化 pending 意图、复核后删除、再登记结果；日志故障或中断明确保留待核对记录，CLI 不误报、不自动重试。
2. pn 在解析时验证非负与可精确序列化范围；异常只使当前条目失败，不打断后续新图／重复图／预演。
3. 当前格式先按输入版本校验再升级、提交前验证目标版本，目标失败事务回滚；删除改路线前的专用识别分支、旧 schema fixture 与测试，基线 5 及 schema 本身不变。
4. 没有展示版本时保留占位卡片及直接属性，计数与分页一致；详情／预览明确提示，不自动挑其他文件、不发空媒体请求，版本变化时清掉旧缩放与加载失败状态。

复杂改动在 PR 内保留职责拆分，合入 main 继续 Squash；不改写已合并历史。
