# 新模型实施与验收（2026-10-28）

需求以 [design.md](design.md) v0.10 为准，简化决定见 [ADR 0010](decisions/0010-图片直接属性与原名增量导入.md)。旧库处理继续按 ADR 0009；T0 的多组共享 tag 与页码必填安排已被取代，不再当作实现依据。

## T1 本次交付

- 新格式 application_id=`0x41475259`、user_version=5；只读预检拒绝旧 v1～v4／未知／过新／不完整库，init 不覆盖非空目录。不转换旧记录、文件或日志。
- 图片与文件版本分离；直接图片 tag、画师与账号、平台发布／可空页码／时间、核查状态、证据和导入记录。无作品组／隐式组／标签继承。
- 新文件保留可用原名和扩展名大小写，所有识别结果进入收件箱；重名必要后缀、跨平台安全字符与长度限制。
- 外部目录再次选择：hash＋实际副本校验；复用已存在身份，保留画师、内容 tag、人工来源与归档状态，新增名称／证据不丢，同输入／规则去重。外部减少不删图库，不是镜像或后台监控。
- 副本损坏／缺失报错、不自动覆盖，不将重复源文件列为可删除。独占目标复制、校验落盘和确认后重新校验删源；预演只读不写库。
- 列表先按图片分页，再批量读多来源／tag／画师，不因关系数量重复卡片；来源建议是数组，不隐藏为旧单条字段。
- 导航与只读浏览为收件箱／已归档；保留有无建议筛选。新 `/api/navigation`、`/api/archived`；删除旧文件夹入口，旧书签明确提示失效。
- 固定一行来源 ID／疑似 ID／原名标题；现有选择、预览、触摸缩放、帮助与竞态守护继续保留。

**不包含**：检查页、多行链接提交、人工确认、归档／强制归档／撤销、画师／角色编辑、相似判定或版本合并。结构中有这些关系不等于用户入口已交付。当前导入只能产生收件箱新图，已归档查询供 T2 接入，不用 SQL 手改图库代替产品功能。

## 后续小步交付

### T2 核查与归档

- 默认逐图检查，来源预填，一行一个链接追加；坏行独立报错，已有来源单独解除。
- 多选是有效链接 × 每张所选图，明确确认范围；pn 可空，不猜 p0。用户核对具体帖子即可确认，时间与页码不额外制造门槛。
- 至少一条已确认具体发布可正常归档，无来源允许显式强制；批量混合缺项先列清单，用户另选，不自动部分执行。
- 两区文件移动与日志／撤销成套：复制校验、目标占用、失败与中断恢复；不误以为 SQLite 事务能撤回磁盘操作。
- 保存／下一张不隐式归档；补来源不自动退回收件箱；文件大小按当前展示版本读取，可复用暂停分支实现并重测。

### T3 直接属性与检索

- 图片直接加／删角色等 tag，画师与多平台账号绑定，支持批量并明确范围，不要求建组。
- 角色补全／最近使用／默认 tag 按使用流程实现；不提前做复杂别名词库、通用标签引擎。
- 平台发布 ID 查询返回相关图片，无需页码；角色、画师、平台可组合，结果按图片身份去重。
- 属性编辑与对应撤销交付，合作作者／同帖多位置等扩展按真实反馈评审。

### T4 与其他后续

- 最小平台规则包，官方／自定义统一格式、版本、命中次序、安全校验与试运行另审，不绑定画师库或任意脚本。
- 文件扫描找回／missing、手动版本关联与拆开、展示版本切换、原文件追溯不阻塞整理闭环。
- Android APK、下载器、结构化导出／恢复、双端合并仍按后续里程碑；不引入旧开发库迁移义务。
