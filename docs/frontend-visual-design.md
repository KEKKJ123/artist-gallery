# 前端可视化设计：操作完成提示（Toast）

> **状态：已在 `feat/archive-toast` 实现，设计待红豆确认。** 按 [AGENTS.md](../AGENTS.md)，界面风格与交互约定的变更需先确认；本文不改变 [frontend-style.md](frontend-style.md) 已有条款，只记录其第 5 节“完成后提示”的落地方式，以及与该节原文仍有出入的地方（见第 3 节“撤销入口”）。
> 配套文档：状态转移见 [frontend-state-transitions.md](frontend-state-transitions.md)，调试方法见 [frontend-debugging.md](frontend-debugging.md)。
> 本文依据 `frontend/src/components/ToastNotice.vue`、`stores/review.js`、`App.vue` 及 `frontend/tests/toast-notice.test.js`、`review-store.test.js` 整理。**样式相关结论（位置、层级、窄屏行为）来自源码，没有在真实浏览器里逐一目测**，见第 6 节。

## 1. 目标与改动前的情况

**目标**：操作成功后，在页面右上角显示一个小提示，不遮挡、不阻断页面其他交互，约 3 秒后自动消失。

**改动前**（T2 基线 `1fa2304`）：

| 场景 | 表现 | 问题 |
|---|---|---|
| 单张正常归档 | 清单弹窗出现，自动执行，成功后关闭；成功信息只是工具栏里的一行小字 | 弹窗在请求期间一直显示，成功信息不显眼，也不会消失 |
| 多张／强制归档 | 清单弹窗，确认后执行 | 行为正确，成功后同样只有工具栏小字 |
| 撤销、保存、恢复 | 同样写入工具栏小字 `review.notice` | 提示不统一 |

原因：`prepareArchive` 先把计划写入 `archivePlan`（弹窗以 `v-if="review.archivePlan"` 显示），再自动调用 `archive()`。详见状态文档第 3 节。

**现状**：上述两个问题均已处理——单张正常归档不再写入 `archivePlan`，成功提示统一走 `ToastNotice`，工具栏小字已删除。

## 2. 视觉与位置

```text
┌──────────────────────────────────────────────┐
│ 收件箱  共 30 张        …  ◐ ⟳ ? ▥          │ ← TopBar（不被盖住）
├──────────────────────────────────────────────┤
│ [开始逐图检查] … [撤销最近一次]   ┌──────────────────┐
│                                   │ 已归档 1 张；来源…  │ ← Toast
│                                   └──────────────────┘
│            缩略图网格（可正常点击、滚动）            │
```

| 项目 | 实现 |
|---|---|
| 位置 | `position: fixed; top: 56px; right: 12px`，在顶栏下方、窗口右侧 |
| 尺寸 | 容器 `max-width: min(360px, calc(100vw - 24px))`；文字 13px，`overflow-wrap: anywhere` 换行，不撑宽 |
| 配色 | 只用 `theme.css` 已有变量（`--bg-elev`、`--fg`、`--border`、`--radius`），深浅色主题自动适配；未新增颜色 |
| 层级 | `z-index: 58`。现有层级：导航抽屉 30／31、预览 50、操作弹窗 55、快捷键帮助 60。提示高于预览和操作弹窗，低于快捷键帮助 |
| 动画 | 淡入加 6px 位移，时长取 `--dur`（120ms）；`prefers-reduced-motion` 下组件内显式取消过渡 |

**`top: 56px` 是固定值，不随顶栏高度变化**：它按桌面顶栏的大致高度取的。顶栏在窄屏换行变高时，提示可能压住顶栏下沿；检查页（顶栏隐藏、改用 `review-header`）里提示则位于页头区域下方。是否改成按实际顶栏高度定位，见第 7 节遗留问题。

## 3. 交互规则

| 项目 | 实现 |
|---|---|
| 不遮挡交互 | 外层容器 `pointer-events: none`，只有提示框本身 `auto`；无遮罩层，不抢焦点，不拦截键盘 |
| 显示时长 | 3000ms；`seq` 每次递增即重新显示并重新计时，**相同文字也会再次显示**（不比较文字） |
| 悬停暂停 | 鼠标进入提示框停止计时，移开后**重新计满 3 秒**，不接着剩余时间 |
| 窄屏和触屏 | `@media (max-width: 520px), (hover: none)` 下提示框也设为 `pointer-events: none`：窄屏工作栏按钮会换行铺满，提示会压在按钮上，触屏也没有悬停。代价是这两种情况下放弃悬停暂停 |
| 多条提示 | 只保留最新一条，不堆叠、不排队 |
| 无障碍 | 外层常驻 `role="status"` + `aria-live="polite"`，节点始终存在，读屏器才会播报 |
| **撤销入口** | **提示里没有“撤销”按钮**；撤销只通过工具栏的“撤销最近一次”进行，提示消失后仍可倒序连续撤销 |

**撤销入口与 [frontend-style.md](frontend-style.md) 第 5 节不一致**：该节写的是“完成后提示‘已归档 3 张　[撤销]’”。本实现没有做提示内按钮，`toast-notice.test.js` 还明确断言了“没有撤销按钮”。这是否可接受需要红豆确认；如果需要，要给组件加撤销入口，并重新考虑 3 秒是否足够以及窄屏的点击穿透（两者互相冲突：窄屏放行点击后按钮就点不到）。

### 哪些信息用 Toast，哪些不用

| 类别 | 展示方式 | 理由 |
|---|---|---|
| 归档、撤销、保存资料、追加来源、文件恢复成功 | **Toast**，3 秒消失 | 结果已落库，用户只需知晓 |
| 失败、版本冲突、图库切换 | 保持现有提示条（`review.error`），**不自动消失** | 用户必须看到并处理，3 秒会漏看 |
| 草稿同步状态 | 保持检查页内的 `draft-status` | 持续状态，不是一次性事件 |
| 强制／多图归档的清单、多选追加来源范围确认、文件恢复 | 保持模态弹窗 | 属 ADR 0007 要求的确认，不能改成提示 |

**需要用户处理的“成功”信息也会走 Toast**：保存资料时若仍有错误行，提示文字是“有效内容已保存；错误行仍留在草稿，请纠正后继续”。这条现在同样 3 秒后消失。错误行本身仍留在草稿和 `lines` 里，检查页会逐行显示，所以信息没有丢；但“提示里的说明”会消失，是否改为常驻见第 7 节。

## 4. 组件与接口

遵循 frontend-style 第 8 节“组件手写、运行依赖尽量少”，无新增依赖。

```text
components/ToastNotice.vue   新增：只负责显示与计时，不读 store
stores/review.js             新增 noticeSeq 与 announce(text)，各处成功提示统一走它
App.vue                      挂载 <ToastNotice :message="review.notice" :seq="review.noticeSeq" />，删除工具栏小字
```

| props | 含义 |
|---|---|
| `message: string` | 提示文字，空字符串不显示 |
| `seq: number` | 每次递增驱动显示与计时 |
| `duration: number` | 默认 3000 |

没有事件、没有撤销相关 props。

- 组件不 import store，由 `App.vue` 传 props，避免组件反向依赖状态；计时器在卸载时清理（`toast-notice.test.js` 断言卸载后无遗留计时器）。
- `announce(text)` 只做两件事：写 `notice`、`noticeSeq++`。`start()` 仍会清空 `notice` 文字，但不会让正在显示的提示消失——可见性由组件自己的 `visible` 决定。
- 使用 `announce` 的位置：保存资料、归档、撤销、文件恢复、多选追加来源。失败路径仍写 `error`，不调用 `announce`。

## 5. 归档流程的配套改动

单张正常归档预检通过后直接执行，**不再写入 `archivePlan`**，所以清单弹窗不会出现；强制、多张或有缺项时仍写入并显示清单，确认规则不变。流程与取舍见 [frontend-state-transitions.md](frontend-state-transitions.md)。

## 6. 测试覆盖与验证边界

已有自动化测试：

| 测试 | 覆盖 |
|---|---|
| `toast-notice.test.js` | 显示后 3 秒消失；新提示重新计时、相同文字再次显示；悬停暂停并重新计满；`aria-live` 容器常驻、无撤销按钮；空消息不显示、卸载无遗留计时器 |
| `review-store.test.js` | 单张正常归档执行期间 `archivePlan` 为 null 且成功后序号加一；有缺项或强制归档停在清单、不执行、不发成功提示；归档失败写入 `error`、不发成功提示、`busy` 复位 |

**自动化测试没有覆盖的部分**（目前只是读源码，没有在浏览器里确认）：

- 提示框以外区域和顶栏按钮在提示显示期间确实可点击（`pointer-events` 的实际效果）。
- `top: 56px` 在桌面、窄屏、检查页三种布局下与顶栏的关系。
- `max-width: 520px` 与 `hover: none` 两个媒体查询的实际触发效果，以及深浅色主题下的观感。
- 提示与确认清单、预览层、快捷键帮助同时出现时的层叠顺序。

## 7. 遗留问题（待红豆决定）

1. **撤销入口**：是否要把“撤销”做进提示（与 frontend-style 第 5 节一致），还是接受只用工具栏按钮并更新那一节。
2. **有错误行时的保存提示**：是否保持常驻，而不是 3 秒后消失。
3. **提示的垂直位置**：是否随顶栏高度动态定位，替代固定的 `56px`。
4. **窄屏和触屏的点击穿透**：目前放弃了悬停暂停，若以后加撤销按钮需要重新设计。

## 8. 明确不做

- 不引入第三方 Toast／组件库。
- 不增加持久化、历史列表或通知中心。
- 不改变归档的确认规则：多图和强制归档的清单确认不能因为有撤销或有 Toast 而取消（ADR 0007、AGENTS 规则 10）。
- 改动 `frontend/` 后须 `npm test`、`npm run build` 并提交 `src/artist_gallery/server/static/`，否则 CI 的 `frontend` 任务会失败。
