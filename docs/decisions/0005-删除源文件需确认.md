# 0005 导入只复制；删除源文件需用户确认
- 日期：2026-10-27
- 状态：采纳；取代 0002 中"导入默认移动"的部分

## 背景
0002 规定导入 = 复制 → 校验 → 自动删除源文件。红豆希望把"删不删源文件"作为独立的二次确认交给用户，以应对特殊情况（例如源文件夹还要留作他用、想先在图库里看一眼结果）。

## 决定
1. `import_files()` 只复制并入库，**永远不删源文件**。
2. 新增 `delete_sources(report)`，只在用户确认后调用。删除每个文件前再次检查：
   - 图库副本存在且 sha256 与导入时一致；
   - 源文件存在且 sha256 与导入时一致（导入后被修改过的不删）。
   任何一项不满足就跳过并说明原因。
3. 只有本次真正新入库的文件可删；重复跳过、失败、预演的源文件一律不删。
4. 交互方式：
   - CLI：`--delete-source ask|yes|no`，默认 `ask`（导入完成后提示 `[y/N]`，默认不删）；非交互环境下 `ask` 视为不删。
   - Web / APK（M1 起）：导入结果页提供"删除源文件"复选框，默认不勾选。
5. 每次删除写入 op_log（kind = `delete_source`）。

## 理由与代价
- 删除变成用户看过结果之后的明确动作，误删的可能性最低。
- 代价：多一步确认；默认不删，源文件夹需要用户自己清理或在确认时选"是"。
- APK 默认用 Photo Picker 导入（ADR 0004），本来就拿不到删除源文件的权限，所以这一步在 APK 上只对"共享文件夹"高级模式有意义。
